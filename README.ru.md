# RAGSpark

**Приватный RAG-комплекс для NVIDIA DGX Spark на базе RAGFlow.**

[English version](README.md)

> **Статус: pre-alpha.** Проект создаётся открыто. Установщик работает на
> DGX Spark (этапы 3–5), но возможны изменения; не ставьте его на машину,
> данные которой вам нужны. См. план работ ниже.

## Что это

RAGSpark превращает DGX Spark в самодостаточную систему вопросов и ответов по
документам: вы загружаете документы, задаёте вопросы и получаете ответы со
ссылками на источники. Все модели работают локально, данные не покидают машину.

- **RAGFlow** — разбор документов, разбиение на фрагменты, поиск и веб-интерфейс
- **vLLM** — LLM, модель эмбеддингов и реранкер на GPU GB10
- **Одна CLI** — установка, смена LLM, бэкап данных, восстановление и удаление
- **Каталог моделей** — выбор модели под ваше железо; у каждой пометка
  *проверена* или *экспериментальная*
- **Два режима** — `single` (один DGX Spark) и `stack` (два DGX Spark,
  соединённые по QSFP, для модели, которая не помещается в один)

## Требования

| | |
|---|---|
| Железо | NVIDIA DGX Spark (GB10, arm64, 128 GB общей памяти) |
| ОС | DGX OS 7.x (Ubuntu 24.04 arm64) |
| Драйвер | NVIDIA 580.x (закреплён — новые ветки дают регрессии на GB10) |
| Диск | около 150 GB под образы и веса моделей |
| Режим stack | второй DGX Spark, кабель QSFP, ещё около 190 GB на каждом узле |

## Установка

```bash
git clone https://github.com/0ffch41n/ragspark.git
cd ragspark
sudo ./install.sh
```

Установщик проверяет машину, скачивает образы и веса моделей, запускает стек
и завершает работу приёмочной проверкой. Дальше —
`sudo ragspark status | start | stop | logs | uninstall`. Руководство:
[docs/INSTALL.ru.md](docs/INSTALL.ru.md); два узла — его раздел «Режим stack».

## Компоненты

| Компонент | Версия | Примечание |
|---|---|---|
| RAGFlow | 0.27.2 | собирается под arm64 этим проектом, с задокументированными исправлениями — официальных arm64-образов нет ([как](docs/BUILD.ru.md)) |
| Elasticsearch | 8.11.3 | версия, которую закрепляет RAGFlow |
| MySQL | 8.0 | метаданные RAGFlow |
| Valkey | 8 | очередь задач RAGFlow |
| Объектное хранилище (pgsty/silo) | закреплено RAGFlow | поддерживаемый форк MinIO; официальные образы MinIO отозваны |
| vLLM | своя для каждой модели | официальные образы с Docker Hub, закреплены по хешу; DeepSeek V4 в режиме stack — на сборке сообщества ([D20](docs/DECISIONS.ru.md)) |

Модели по умолчанию: Qwen 3.8 27B NVFP4 с предсказанием нескольких токенов
(LLM), deepvk/USER-bge-m3 (эмбеддинги), BAAI/bge-reranker-v2-m3 (реранкер); все
три — на официальном образе vLLM 0.27.1. Qwen 3.6 35B-A3B — быстрая
альтернатива: примерно в 4 раза быстрее, те же ответы на первых уровнях чата
(Naive, Low), слабее на ответах из двух частей выше них. Её можно выбрать при
установке или позже командой `sudo ragspark llm`. См.
[catalog/models.yaml](catalog/models.yaml) и
[docs/VALIDATION.ru.md](docs/VALIDATION.ru.md), раздел 14.

На двух DGX Spark режим `stack` запускает DeepSeek V4 Flash (284B, MoE) сразу
на обоих: примерно вдвое быстрее модели по умолчанию, на тестовых наборах
отвечает так же, читает сканы; на собственной паре RAGSpark она в работе
([docs/VALIDATION.ru.md](docs/VALIDATION.ru.md), разделы 17–18).

**Русские документы:** настройки RAGFlow по умолчанию плохо работают с русским,
и RAGSpark их меняет — PDF читается по текстовому слою, а поиск опирается на
реранкер. Агентные режимы чата RAGFlow (Low … Ultra) не работали с русскими
документами и исправлены в образе RAGSpark; чат начинает с быстрого
классического режима. Замеры — в [docs/VALIDATION.ru.md](docs/VALIDATION.ru.md).
Отсканированные PDF читаются зрением самой LLM: около 20 с на страницу с LLM по
умолчанию, около 7 с Qwen 3.6.

## Принципы

1. **Установщик не меняет хост** сверх того, что объявляет: никаких правок DNS,
   никаких системных пакетов, которые он не может чисто удалить.
2. **Удаление — зеркало установки**: всё созданное записывается в манифест и
   удаляется строго по нему.
3. **В сеть смотрит только веб-вход**; все остальные порты привязаны к `127.0.0.1`.
4. **Установка не завершена, пока RAG не ответил**: последний шаг загружает
   документ, задаёт вопрос и проверяет ответ со ссылкой на источник.
5. **Реестры ненадёжны**: офлайн-пакет и зеркало образов — базовые функции.
