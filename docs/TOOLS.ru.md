# Инструменты

[English version](TOOLS.md)

Самостоятельные скрипты на Python для настройки и проверки стека RAGSpark. Им
не нужно ничего, кроме стандартной библиотеки Python. Пять из них
запускаются *внутри* контейнера RAGFlow: оттуда сервисы vLLM доступны по имени,
есть собственное шифрование пароля RAGFlow, а данные суперпользователя и
настройки LLM уже лежат в окружении контейнера (`compose/.env` и файл LLM).

`ragflow_models.py` и `acceptance.py` установщик запускает сам. Команды ниже
выполняются из каталога `compose/` — на установленной машине это
`/opt/ragspark/compose`, а инструменты лежат в `/opt/ragspark/tools`.

## ragflow_models.py — регистрация моделей в RAGFlow

Регистрирует обслуживаемые vLLM модели — LLM, эмбеддинги и реранкер — в учётке
администратора RAGFlow и назначает их моделями по умолчанию. Повторный запуск
ничего не меняет.

```bash
# только проверка
sudo docker compose exec -T ragflow \
  sh -c 'cd /ragflow && PYTHONPATH=/ragflow .venv/bin/python - --check' < ../tools/ragflow_models.py
# применить
sudo docker compose exec -T ragflow \
  sh -c 'cd /ragflow && PYTHONPATH=/ragflow .venv/bin/python -' < ../tools/ragflow_models.py
```

Запись для LLM берётся из `RAGSPARK_LLM_NAME`, `RAGSPARK_LLM_CONTEXT` и
`RAGSPARK_LLM_TOOLS`, которые выбранный файл LLM задаёт сервису RAGFlow;
`--spec ФАЙЛ` заменяет весь список.

| Статус | Значение |
|---|---|
| `[OK]` | уже как нужно |
| `[TODO]` | будет изменено (только в `--check`) |
| `[SET]` | модель по умолчанию назначена или переназначена |
| `[FAIL]` | требует внимания; код выхода 1 |

Существующие экземпляры не изменяются никогда. Если экземпляр указывает на
другой адрес, скрипт сообщает об этом и не трогает его. Модель по умолчанию,
ссылающаяся на удалённую модель — так бывает после удаления и пересоздания
экземпляра, — обнаруживается по идентификатору и переназначается.

## acceptance.py — приёмочная проверка

Создаёт базу знаний и чат «RAGSpark — пример» («RAGSpark sample» при
`--lang en`) с настройками RAGSpark, загружает пример PDF, ждёт разбора и
задаёт чату вопросы из примера. Ответы должны содержать нужные факты,
ссылаться на документ и не содержать знаков CJK; на вопрос, ответа на который
в документе нет, чат должен выдать свой текст «нет ответа». Первый вопрос
задаётся ещё раз на уровне Low (агентный конвейер). База знаний и чат с тем же
именем заменяются; новые остаются как пример. Чат «Ассистент» («Assistant»)
без базы знаний создаётся, если его нет, и проверяется простым вопросом;
существующий остаётся как есть. Разговоры, открытые проверкой, удаляются.
Подробнее: [INSTALL.ru.md](INSTALL.ru.md), «Приёмочная проверка».

```bash
sudo ragspark acceptance              # на установленной машине
# вручную:
sudo docker compose cp ../acceptance/. ragflow:/tmp/ragspark-acceptance
sudo docker compose exec -T ragflow \
  sh -c 'cd /ragflow && PYTHONPATH=/ragflow .venv/bin/python - --lang ru' < ../tools/acceptance.py
```

| Параметр | Действие |
|---|---|
| `--lang ru\|en` | имена, подсказки и текст «нет ответа» в примере |
| `--dir DIR` | каталог с файлами примера внутри контейнера (по умолчанию `/tmp/ragspark-acceptance`) |
| `--cleanup` | удалить базу знаний и чат примера после проверки (чат ассистента остаётся) |
| `--no-agentic` | не задавать вопрос на уровне Low |
| `--assistant-only` | только создать и проверить чат ассистента (установщик с `--skip-acceptance`) |

## rag_eval.py — качество разбора и поиска

Только читает. Для каждого документа базы знаний показывает число фрагментов,
долю кириллических букв и число искажённых слов — латинских двойников вроде
`Pa3beM`, которые даёт распознавание, не знающее кириллицы. Затем прогоняет
набор вопросов через API поиска в пяти настройках и проверяет, найден ли
фрагмент с ожидаемыми фактами.

```bash
sudo docker compose exec -T ragflow \
  sh -c 'cd /ragflow && PYTHONPATH=/ragflow .venv/bin/python - --dataset test' < ../tools/rag_eval.py
```

| Ключ | Что делает |
|---|---|
| `--dataset ИМЯ` | какую базу знаний проверять (по умолчанию `test`) |
| `--questions ФАЙЛ` | JSON-список `{"q": ..., "expect": [...]}`; `"expect": null` — вопрос, ответа на который в документах нет |
| `-v` | показать примеры искажённых слов |
| `--why` | для не найденных вопросов повторить поиск с порогом 0 и показать, на каком месте ответ |
| `--probe` | для не найденных вопросов оценить фрагмент с ответом напрямую реранкером в нескольких видах |

Обозначения: `#N` — место первого фрагмента с ожидаемыми фактами; `miss` — нет
в первых N; `none` — ничего выше порога; `ok` — на вопрос без ответа правильно
ничего не найдено; `LEAK` — на вопрос без ответа что-то нашлось (показана
лучшая оценка).

Встроенный набор вопросов составлен по русской инструкции к материнской плате
MSI MPG B550 Gaming Plus (фрагмент на 39 страниц). Сама инструкция в RAGSpark
не входит; для других документов используйте `--questions`.

## mode_eval.py — сравнение режимов чата

Задаёт одному чату одни и те же вопросы на каждом уровне рассуждений из
списка под полем ввода — 0 Naive, 1 Low, 2 Medium, 3 High, 4 Ultra (D19) —
через API и выводит для каждого ответа время, вердикт и число источников,
затем итог по уровням. Открытые разговоры в конце удаляются.

```bash
# чат примера, вопросы примера приёмочной проверки, Naive, Low и Medium:
sudo docker compose exec -T ragflow \
  sh -c 'cd /ragflow && PYTHONPATH=/ragflow .venv/bin/python - --modes 0,1,2' < ../tools/mode_eval.py
# временный чат над базой знаний «test», вопросы по MSI:
sudo docker compose exec -T ragflow \
  sh -c 'cd /ragflow && PYTHONPATH=/ragflow .venv/bin/python - --dataset test --set msi' < ../tools/mode_eval.py
```

| Параметр | Действие |
|---|---|
| `--chat ИМЯ` | какой чат спрашивать (по умолчанию «RAGSpark — пример») |
| `--dataset ИМЯ` | вместо этого временный чат над этой базой знаний с настройками RAGSpark, потом удаляется |
| `--modes 0,1,2,3,4` | какие уровни запускать (по умолчанию все пять) |
| `--set sample\|msi` | встроенные вопросы: 7 + 1 по примеру приёмочной проверки (по умолчанию) или набор этапа 3.1 по MSI |
| `--questions ФАЙЛ` | вместо них JSON-список `{"q": ..., "expect": [...]}`; элемент `expect` может быть списком вариантов; `"expect": null` — вопрос без ответа в документах |
| `--timeout С` | секунд на ответ (по умолчанию 900) |
| `--keep-sessions` | не удалять разговоры |
| `--trace` | под каждым ответом — журнал хода работы, который агентные уровни показывают в веб-интерфейсе как «размышления» (поиски, оставленные фрагменты, составление ответа) |

Вердикты: `ok`; `miss` — нет ожидаемых фактов; `no-src` — нет источников;
`cjk` — в ответе знаки CJK; для вопроса без ответа в документах `ok` — текст
чата «нет ответа», `LEAK` — другой ответ с источниками, `LEAK-own` — другой
ответ без источников; `TIMEOUT`, `ERROR`. Итог считает `ok` среди вопросов с
ответом и среди вопросов без него. На Medium и выше ответ занимает 1–2 минуты.

## model_probe.py — язык и скорость LLM

Задаёт LLM русские вопросы в трёх режимах — с рассуждениями, без них и без них
с температурой 0,7 — и показывает скорость и сколько ответов содержат
китайские, японские или корейские символы.

```bash
sudo docker compose exec -T ragflow /ragflow/.venv/bin/python - < ../tools/model_probe.py
# любой OpenAI-совместимый сервер:
VLLM_URL=http://host:8000 MODEL=<имя модели> python3 tools/model_probe.py
```

## pin_images.py — закрепление образов хешем

Запускается на хосте. Для каждой строки `image:`, где указан только тег,
записывает хеш локального образа из реестра (`имя:тег@sha256:…`); уже
закреплённые строки сверяет с локальным образом. Нужен после смены тега и
скачивания нового образа.

```bash
sudo python3 tools/pin_images.py compose/compose.yaml compose/llm/*.yaml          # закрепить
sudo python3 tools/pin_images.py --check compose/compose.yaml compose/llm/*.yaml  # только отчёт
```
