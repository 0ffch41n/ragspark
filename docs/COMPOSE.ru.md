# Запуск RAGSpark через Docker Compose

[English version](COMPOSE.md)

Каталог [compose/](../compose/) запускает весь режим `single` на одном DGX
Spark: RAGFlow, его базы данных и три сервера моделей vLLM. Установщик
(этап 3.3) возьмёт шаги ниже на себя; пока они выполняются вручную.
Решение: D17 в [DECISIONS.ru.md](DECISIONS.ru.md).

## Файлы

| Файл | Назначение |
|---|---|
| `compose/compose.yaml` | все сервисы, кроме образа и флагов LLM |
| `compose/llm/<модель>.yaml` | по файлу на LLM: образ, флаги vLLM, что регистрировать в RAGFlow |
| `compose/env.example` | шаблон настроек; `init-env.sh` делает из него `.env` |
| `compose/init-env.sh` | создаёт `.env` со случайными паролями и часовым поясом хоста |
| `compose/.env` | настройки и пароли этой установки (права 600, в git не попадает) |

`COMPOSE_FILE` в `.env` соединяет `compose.yaml` с выбранным файлом LLM,
поэтому любую команду `docker compose` нужно запускать из каталога `compose/`.

## Сервисы

| Сервис | Образ | Роль | Память |
|---|---|---|---|
| `vllm-embed` | vLLM 0.27.1 | эмбеддинги, `deepvk/USER-bge-m3` | 5% общей памяти |
| `vllm-rerank` | vLLM 0.27.1 | реранкер, `BAAI/bge-reranker-v2-m3` | 3% |
| `vllm-llm` | из файла LLM | модель для чата (по умолчанию Qwen 3.8 27B NVFP4) | 50% |
| `es01` | Elasticsearch 8.11.3 | полнотекстовый и векторный индекс | до 8 GB |
| `mysql` | MySQL 8.0.40 | метаданные RAGFlow | — |
| `minio` | pgsty/silo | загруженные файлы | — |
| `redis` | Valkey 8 | очереди и кеш | 128 MB |
| `ragflow` | RAGSpark r2 | веб-интерфейс, API, обработка документов | — |

Порт публикует только `ragflow`: его nginx на порту 80 (`RAGSPARK_HTTP_BIND`,
`RAGSPARK_HTTP_PORT`), который отдаёт и веб-интерфейс, и API по пути
`/api/v1`. Остальные сервисы доступны только во внутренней сети `ragspark`, по
имени сервиса.

## Порядок запуска

1. `vllm-embed`, затем `vllm-rerank`, затем `vllm-llm` — по одному, каждый
   ждёт, пока предыдущий сообщит о готовности.
2. `es01`, `mysql`, `minio` и `redis` стартуют сразу, параллельно с моделями.
3. `ragflow` стартует, когда всё перечисленное готово, поэтому он никогда не
   отправляет запрос модели, которая ещё загружается.

Модели запускаются по одной, потому что vLLM рассчитывает размер своего кеша
по памяти, которую измеряет во время запуска. На общей памяти то, что в этот
момент заняла другая стартующая модель, засчитывается ему самому, и маленьким
моделям не остаётся места под кеш.

Замерено 8 октября 2026 года, веса уже в кеше: весь стек — 9 мин 10 с;
эмбеддинги 36 с, реранкер 36 с, LLM 7 мин 11 с, RAGFlow около 45 с.
Перезапуск одной LLM занимает около 5,5 минут, потому что кеш компиляции
сохраняется между запусками.

## Первый запуск

Нужны Docker с NVIDIA runtime (в DGX OS есть и то и другое), локальные образы и
веса моделей в `/srv/ragspark/hf-cache`.

```bash
cd compose
./init-env.sh                       # создаёт .env; существующий не перезаписывает
sudo docker compose config --quiet  # проверяет файлы и .env
sudo docker compose up -d --wait --wait-timeout 2400
sudo docker compose ps
```

`init-env.sh` задаёт суперпользователя `admin@ragspark.local`; если нужен другой
адрес, измените `DEFAULT_SUPERUSER_EMAIL` в `.env` до первого запуска. Пароль —
`ADMIN_DEFAULT_PASSWORD` в `.env`. Оба значения читаются один раз, когда RAGFlow
создаёт суперпользователя.

Затем зарегистрируйте модели в RAGFlow и назначьте их моделями по умолчанию:

```bash
sudo docker compose exec -T ragflow \
  sh -c 'cd /ragflow && PYTHONPATH=/ragflow .venv/bin/python -' < ../tools/ragflow_models.py
```

и откройте в браузере `http://<адрес Spark>/`.

**Весов ещё нет в кеше?** vLLM запускается без выхода в интернет
(`RAGSPARK_HF_OFFLINE=1`) и останавливается, если файла не хватает. Для
первого скачивания поставьте в `.env` `RAGSPARK_HF_OFFLINE=0`, запустите стек и
потом верните `1`.

## Повседневные команды

Все — из `compose/`:

| Задача | Команда |
|---|---|
| состояние | `sudo docker compose ps` |
| журнал одного сервиса | `sudo docker compose logs -f --tail 100 ragflow` |
| остановить всё, данные сохранить | `sudo docker compose down` |
| запустить снова | `sudo docker compose up -d --wait --wait-timeout 2400` |
| перезапустить один сервис | `sudo docker compose restart vllm-llm` |
| оболочка в RAGFlow | `sudo docker compose exec ragflow bash` |

После сбоя контейнеры перезапускаются, но **при загрузке Spark ничего не
стартует само**: если бы контейнеры поднимал сам Docker, они стартовали бы все
сразу и нарушили порядок запуска. После перезагрузки выполните `up`;
установщик добавит для этого службу systemd.

## Смена LLM

Укажите в `COMPOSE_FILE` в `.env` другой файл из `compose/llm/`, выполните
`sudo docker compose up -d --wait`, а затем `tools/ragflow_models.py`, чтобы
зарегистрировать новую модель. Сейчас в каталоге только модель по умолчанию;
остальные появятся на этапе 4.

## Данные

| Том | Содержимое |
|---|---|
| `ragspark_esdata` | поисковый индекс |
| `ragspark_mysql` | пользователи, базы знаний, чаты, настройки |
| `ragspark_minio` | загруженные документы |
| `ragspark_valkey` | очереди задач и кеш |
| `ragspark_ragflow-logs` | журналы RAGFlow |
| `ragspark_vllm-compile-cache` | результаты компиляции vLLM, ускоряют следующие запуски |
| `/srv/ragspark/hf-cache` (каталог хоста) | веса моделей |

`sudo docker compose down -v` удаляет все перечисленные тома — все документы,
пользователей и чаты. Веса в `/srv/ragspark/hf-cache` остаются. Храните `.env`,
пока существуют тома: базы данных принимают только те пароли, с которыми были
созданы.

Журнал каждого контейнера ограничен пятью файлами по 20 MB.

## Неполадки

| Признак | Причина и что делать |
|---|---|
| `up` останавливается с `dependency failed to start` | модель или база данных не стала готовой: `sudo docker compose ps -a` и журнал этого сервиса |
| сервис vLLM завершается с `Free memory on device … is less than desired` | память заняли другие процессы или файловый кеш. Посмотрите `free -g`; кеш освобождается командой `sudo sh -c 'sync; echo 3 > /proc/sys/vm/drop_caches'` |
| сервис vLLM завершается с `LocalEntryNotFoundError` или `offline mode` | весов нет в кеше — см. «Весов ещё нет в кеше?» |
| порт 80 занят | другой веб-сервер или старый стек; измените `RAGSPARK_HTTP_PORT` или остановите его |
