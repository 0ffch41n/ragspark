## 1. Запуск LLM — Qwen 3.8 27B NVFP4

- Образ `vllm/vllm-openai:v0.27.1-aarch64`: vLLM 0.27.1, CUDA 13.0,
  вычислительная способность (12, 1). Чекпоинт NVFP4 распознаётся, выбирается
  `FlashInferCutlassNvFp4LinearKernel` — сборка сообщества не нужна.
- Веса загружаются из кеша примерно за 150 секунд; KV-кеш — около 814 тысяч
  токенов при `gpu_memory_utilization 0.50` (без MTP). Запуск с MTP и захватом
  CUDA-графов — около 7 минут.
- [model_probe.py](../tools/model_probe.py), 5 русских вопросов на режим:

  | Режим | Без MTP | MTP, 3 токена | Ответов с иероглифами |
  |---|---|---|---|
  | с рассуждениями | 10,3 ток/с | — | 0 из 5 |
  | без рассуждений | 10,2 ток/с | — | 0 из 5 |
  | без рассуждений, t=0,7 | 10,2 ток/с | — | 0 из 5 |
  | все режимы, MTP | — | **17,1 ток/с** (19–21 на ответах по контексту) | 0 из 15 |

- Рассуждения: тот же ответ занял 1116 токенов и 108 секунд с рассуждениями и
  101 токен и 10 секунд без них. Выключены на сервере флагом
  `--default-chat-template-kwargs '{"enable_thinking": false}'`; проверено, что
  запрос без параметров не возвращает поле `reasoning`.
- 8 параллельных запросов с MTP: все HTTP 200, по 25–27 секунд, суммарно около
  90 токенов/с; сервер не упал.
- Один из ранних пробных ответов содержал китайский фрагмент («相关信息»);
  приёмочная проверка должна продолжать искать иероглифы.

## 2. Регистрация моделей через API RAGFlow

Снято с веб-интерфейса RAGFlow 0.27.2 и автоматизировано в
[ragflow_models.py](../tools/ragflow_models.py):

| Шаг | Запрос | Тело / примечания |
|---|---|---|
| вход | `POST /api/v1/auth/login` | `{email, password}`; пароль шифруется RSA ключом `conf/public.pem` (`api.utils.crypt.crypt`). Токен приходит в **заголовке ответа** `Authorization`, без `Bearer` |
| подключить провайдера | `PUT /api/v1/providers` | `{"provider_name": "VLLM"}` |
| проверить адрес | `POST /api/v1/providers/VLLM/connection` | `{provider_name, api_key: "", base_url}` |
| модели на сервере | `GET /api/v1/providers/VLLM/models?api_key=x&base_url=…` | возвращает `name`, `model_types` (определяется верно: chat / embedding / rerank), `max_tokens` из vLLM |
| создать экземпляр | `POST /api/v1/providers/VLLM/instances` | `{instance_name, api_key: "", base_url, model_info: [{model_name, model_type: [тип], max_tokens, extra: {is_tools}}]}`; пустой ключ сохраняется как `"x"` |
| список экземпляров | `GET /api/v1/providers/VLLM/instances` | в списке **нет `base_url`**; его даёт `GET …/instances/<id>` |
| изменить экземпляр | `PUT /api/v1/providers/VLLM/instances/<id>` | полная запись |
| идентификаторы моделей | `GET /api/v1/models` | `model_id`, `name`, `instance_name`, `model_type` для каждой модели; идентификатор модели отличается от идентификатора экземпляра |
| назначить по умолчанию | `PATCH /api/v1/models/default` | `{model_id, model_type}`; интерфейс сохраняет каждое поле сразу |
| прочитать умолчания | `GET /api/v1/models/default` | хранится по `model_id`; имена подбираются заново, поэтому устаревший идентификатор может показывать совпадающие имена |
| поиск | `POST /api/v1/retrieval` | `{dataset_ids, question, similarity_threshold, vector_similarity_weight, rerank_id: "BAAI/bge-reranker-v2-m3@ragspark-rerank@VLLM", page_size, rerank_candidates_count}` |

Успешный ответ всегда содержит `{"code": 0}`. Модели живут в учётке
администратора (`tenant_name: "admin’s Kingdom"`).

## 3. Загрузка документов

- **DOCX** (18 KB, русский текст с командами): 3 фрагмента, около 1,5 секунды
  от старта до индекса; три запроса `POST /v1/embeddings` дошли до vLLM.
  Обработчик задач работает без NATS — очереди в Valkey. Строки склеиваются без
  разделителя (`GPUКритерий`): 11 таких мест.
- **PDF** (русская инструкция к материнской плате на 39 страниц, текстовый слой
  есть):

  | Парсер | Время | Фрагментов | Доля кириллицы | Искажённых слов |
  |---|---|---|---|---|
  | DeepDOC | ~2 мин (распознавание 7–9 с, макет ~8 с, таблицы 4–39 с на 12 страниц) | 100 | 0,665 | 194 |
  | Naive | секунды | 41 | **0,835** | **0** |

  Эталон 0,835 — собственный текстовый слой PDF (`pdftotext`).
- Причины в DeepDOC, по исходникам 0.27.2:
  - `deepdoc/parser/pdf_parser.py`, проверка «искажённой кодировки шрифта» на
    уровне страницы: если ≥30% символов страницы из подмножеств шрифтов, <5% —
    иероглифы и >40% — знаки препинания ASCII, текст страницы выбрасывается и
    она распознаётся как картинка. Срабатывает на точках-заполнителях оглавления.
  - Модель распознавания — иероглифы и латиница. Защита от повторного
    распознавания кириллицы есть на уровне отдельных блоков
    (`_ocr_can_represent`), но не в проверке страницы.

## 4. Поиск

Итоговая оценка с реранкером (`rag/nlp/search.py`, `rerank_by_model`):
`(1 − w) × совпадение слов + w × оценка реранкера`, сравнивается с порогом
сходства; `w` — вес векторного сходства.

- С настройками RAGFlow по умолчанию (`w` = 0,3, порог 0,2) нужный фрагмент
  DOCX набрал 0,7 × 0,154 + 0,3 × 0,293 = **0,196** и был отброшен.
- [rag_eval.py](../tools/rag_eval.py) на PDF (Naive), 8 вопросов с ответом и 2
  без ответа:

  | Настройка | До правки: найдено / отсеяно | После правки: найдено / отсеяно |
  |---|---|---|
  | реранкер, 0,3 / 0,2 | 5/8 · 1/2 | 6/8 · 1/2 |
  | реранкер, 0,7 / 0,2 | 5/8 · 2/2 | 7/8 · 2/2 |
  | реранкер, 0,7 / 0,1 | 6/8 · 2/2 | **8/8 · 2/2** |
  | без реранкера, 0,7 / 0,2 | 8/8 · 0/2 | 8/8 · 0/2 |
  | без реранкера, 0,7 / 0,5 | 8/8 · 0/2 | 8/8 · 0/2 |

  Без реранкера вопросы без ответа получили 0,58 — столько же, сколько
  настоящие ответы (0,56–0,62).
- Причина низких оценок реранкера: RAGFlow отправляет ему
  `remove_redundant_spaces(" ".join(tokens))`. Первое регулярное выражение
  функции, `([^a-z0-9.,\)>]) +([^ ])` → `\1\2`, удаляет все пробелы после
  нелатинских символов:

  ```
  "оранжевый 1 гбит с подключение таблица состояний индикатора порта lan"
  → "оранжевый1гбитсподключениетаблицасостоянийиндикаторапортаlan"
  ```

  Английский текст не страдает. Тот же фрагмент, оценённый напрямую
  (`--probe`):

  | Вопрос | Склеенные токены (RAGFlow) | Исходный текст | Только строки с ответом |
  |---|---|---|---|
  | объём памяти | 0,152 | 0,116 | 0,047 |
  | оранжевый индикатор LAN | 0,373 | 0,457 | 0,285 |
  | размеры для M2_2 | 0,320 | 0,640 | 0,960 |

  Токены имени файла, которые RAGFlow дописывает к фрагменту, меняли оценку
  меньше чем на 0,05. LLM не затронута: она получает исходный текст фрагмента.
- Исправление: [patch_search.py](../build/ragflow/patch_search.py) (образ `r2`)
  — реранкер получает исходный текст фрагмента вместе с его ключевыми словами и
  сгенерированными вопросами. Проверено правкой прямо в работающем контейнере,
  а 8 октября 2026 года — на образе `r2`: таблица та же.

## 5. Полный путь

- Чат с Qwen 3.8, база знаний с DOCX, реранкер, `w` = 0,7, порог 0,2:
  «Какая максимальная температура GPU допустима при стресс-тесте?» →
  «≤80 °C, пик ≤90 °C» со ссылкой на источник, на русском.
- Вопрос, ответа на который в документах нет, вернул заданный текст «Empty
  response». RAGFlow отдаёт его, не вызывая LLM, когда ничего не прошло порог,
  поэтому модели нечего выдумывать.
- Новые базы знаний и чаты получили LLM и модель эмбеддингов по умолчанию;
  реранкер пришлось выбирать вручную (D8).

## 7. Установщик (этап 3.3)

Доказательства для D18, собранные 9 октября 2026 года на том же DGX Spark
(DGX OS 7.5, Docker 29.6.2, Compose v5.2.0, Python 3.12.3). Стек этапа 3.2
сначала удалён вместе с томами; образы и веса остались на машине.

- **Офлайн-тесты на Spark:** 19 из 19 прошли с Python и Compose машины.
- **GPU после `systemctl daemon-reload`** (`ragspark check --gpu-reload`):
  тестовый контейнер сохранил GPU при драйвере cgroup `systemd`. Драйвер
  остаётся как есть (D6).
- **Установка** (`sudo ./install.sh`, русский, значения по умолчанию): все
  проверки пройдены; 6 из 6 образов на месте; GPU виден в образе vLLM; стек
  запущен с пустыми томами за **9,4 мин**; модели зарегистрированы;
  приёмочная проверка пройдена за **16 с** — 2 фрагмента с долей кириллицы
  0,992, оба ответа верные и со ссылкой (3 с и 2 с), на вопрос без ответа —
  текст «нет ответа» без вызова LLM. В сети слушают только порты 22 и 80.
- **Проверка весов:** кеш Qwen был полным, но проверка без сети через
  `huggingface_hub` упала с `IncompleteSnapshotError`: она требует три
  служебных файла (`crc32.txt`, `hf_quant_config.json`, пустой
  `safetensors-md5sum.txt`), которые vLLM при своём скачивании пропустил.
  Установщик их докачал (17,5 КБ). Теперь проверка сама читает кеш — снимок,
  на который указывает `refs/main`, `config.json` и все файлы весов из
  индекса, — и полному кешу сеть не нужна.
- **Перезагрузка:** Docker сам запустил `es01` и `ragflow` — два контейнера,
  которые при выключении вышли с ненулевым кодом. Служба остановила их
  (`ExecStartPre`) и запустила стек по порядку: базы данных и эмбеддинги
  сразу, реранкер через 27 с, LLM ещё через 25 с, RAGFlow — когда LLM стала
  готова через 5,5 мин (кеш компиляции). Около 7 мин от старта службы до
  готового стека, ни одного перезапуска контейнеров. После холодной загрузки
  файловый кеш был пуст; моделям не понадобилось его освобождать; в покое
  свободно 36 GiB. `ragspark start` во время загрузки только следила за
  службой.
- **Остановка и запуск** (`ragspark stop`, `ragspark start`): все 8
  контейнеров остановлены; снова запущены по порядку за 6,2 мин.
- **Режимы чата в веб-интерфейсе:** поле ввода чата RAGFlow по умолчанию
  стоит на уровне рассуждений «Low», а он отвечает через агентный конвейер
  RAGFlow. Вопрос там не завершился за 10 минут («Running the rag tool...»);
  запрос оборвал таймаут инструмента (600 с). Первый служебный вызов
  конвейера — извлечение ключевых слов, температура 0,1, без ограничения
  длины (RAGFlow вырезает `max_tokens` из всех запросов) — так и не вернулся:
  vLLM 10 минут генерировал этот один запрос, принимая все токены
  спекулятивного декодирования, — цикл повторов. Тот же запрос, отправленный
  30 раз с ограничением 800 токенов, зациклился 9 раз (`"серверная",
  "серверная", …`). С `frequency_penalty 0.5` — ни одного цикла из 30, все 30
  ответов — корректный JSON; `repetition_penalty 1.1` тоже дал 0 циклов, но
  штрафует и токены промпта, `presence_penalty 1.5` — 2 цикла. Уровень
  «Naive», через который идёт приёмочная проверка, отвечает за секунды.
  Исправлено в образе `r3`: раздел 8.

## 8. Режимы чата и образы `r3` и `r4`

Доказательства для D19, собранные 12–13 и 19 октября 2026 года на том же DGX
Spark со стеком, установленным на этапе 3.3. Каждое исправление сначала
вносилось в работающий контейнер (`build/ragflow/patch_*.py` внутри него,
затем перезапуск) — `r2` для восьми правок, вошедших в `r3`, и `r3` для
четырёх, вошедших в `r4`; [tools/mode_eval.py](../tools/mode_eval.py) задаёт
одному чату одни и те же вопросы на каждом уровне рассуждений через API.

Опубликованный образ `r3` собран раньше двух правок, которые D19 к нему
относит: сужение по кириллическим ключевым словам и обязательный вызов `rag` в
первом круге написаны после сборки (13:59 против 12:12 14 октября 2026 года),
поэтому в самом образе их нет и работали они только как горячая правка
контейнера. `r4` — первый образ, который несёт все двенадцать. Проверено по
меткам правок `build/ragflow/patch_*.py`: девять в образе `r3` против
пятнадцати в контейнере, на котором сделаны замеры ниже, — и эти пятнадцать
совпадают байт в байт с набором образа `r4`, поэтому замеры описывают `r4`.

- **Циклы служебных вызовов.** Запрос ключевых слов агентного конвейера в
  том виде, в каком его шлёт RAGFlow (температура 0,1, без ограничения
  длины), здесь с пределом 800 токенов; 5 вопросов × 6, по пять параллельно:

  | Вариант | Циклы | Корректный JSON | Нормальные ответы, токенов | Время |
  |---|---|---|---|---|
  | как шлёт RAGFlow | **9/30** | — | 60–704 | 134 с |
  | `repetition_penalty 1.05` | 2/30 | — | 41–338 | 70 с |
  | `presence_penalty 1.5` | 2/30 | 28/30 | 67–121 | 62 с |
  | совет Qwen: t 0,7, top_p 0,8, presence 1,5 | 1/30 | 29/30 | 66–187 | 56 с |
  | `repetition_penalty 1.1` | 0/30 | 30/30 | 38–215 | 57 с |
  | **`frequency_penalty 0.5`** | **0/30** | **30/30** | 59–126 | 41 с |

  Цикл повторяет одно слово или фразу (`"серверная", "серверная", …`).
  Выбран `frequency_penalty`: он учитывает только повторы в самом ответе, а
  `repetition_penalty` штрафует и токены промпта. Иероглифов не дал ни один
  вариант.
- **Фильтр kNN.** «Когда проходят плановые работы?» к документу, где
  написано «Плановое обслуживание проводится…»: до исправления — ни одного
  кандидата ни в одной настройке, даже при пороге 0; после — 1-е место в
  четырёх настройках из пяти (кроме реранкера 0,3/0,2). На руководстве этапа
  3.1 итоги матрицы §4 не изменились ни в одной настройке: реранкер 0,7/0,1 —

## 10. Отсканированные документы

Доказательства для части D14 про сканы, собраны 20 октября 2026 года на чистой
установке из раздела 9 (`r4`); три правки `build/ragflow/patch_scans.py`
вносились в работающий контейнер по одной. Тестовый документ — руководство
этапа 3.1, превращённое в скан: каждая страница отрисована при 150 dpi в
оттенках серого, слегка размыта и сохранена в JPEG с качеством 70, так что
текстового слоя в PDF нет совсем. Замер — [tools/rag_eval.py](../tools/rag_eval.py)
с его набором вопросов по MSI; «зрение» — работающая Qwen 3.8 27B,
зарегистрированная второй раз как зрячая модель, никакой другой модели не
загружено.

- **Почему DeepDOC не читает русский.** Две причины, обе в коде. В словаре его
  распознавателя (`rag/res/deepdoc/ocr.res`) 6623 записи: 6277 иероглифов и
  одна из 33 строчных русских букв. А `_is_garbled_by_font_encoding` в
  `deepdoc/parser/pdf_parser.py` стирает текстовый слой страницы, если не
  меньше 30% её символов взяты из подмножеств шрифтов и
  `cjk_ratio < 0.05 and punct_ratio > 0.4`; кириллица не входит ни в одну из
  долей, так что на русской странице решает одна пунктуация. На цифровом
  руководстве так стёрлись страницы 1–2 — оглавление, 69% и 85% точек, — и их
  распознало как картинки. Когда кириллица считается текстом (правка 1), эти
  страницы сохраняют слой: искажённых слов 194 → 164, доля кириллицы
  0,665 → 0,679. Остальные 85% мусора дают области, которые DeepDOC
  распознаёт всегда, — скриншоты BIOS, — и текстовый слой их не спасёт.
- **Скан через каждый парсер:**

  | Парсер | Время | Фрагментов | Кириллица | Искажённых слов | Найдено (rr .7/.1) | Отклонено вопросов без ответа |
  |---|---|---|---|---|---|---|
  | Plain Text | 3 с | 0 | 0,000 | 0 | 0/8 | —¹ |
  | DeepDOC | 145 с | 89 | 0,000 | 1066 | 0/8 | —¹ |
  | зрение, как есть | 675 с | 39 | 0,823 | 1 | 7/8 | 2/2 |
  | зрение, температура 0 (правка 2) | 675 с | 40 | 0,818 | 2 | 7/8 | 2/2 |
  | **зрение, температура 0, целые таблицы (правки 2–3)** | 674 с | 43 | **0,818** | **2** | **8/8** | **2/2** |
  | *цифровое руководство, Plain Text, все правки, для сравнения* | 6 с | 41 | 0,835 | 0 | 8/8 | 2/2 |

  ¹ порог не проходит ничего ни по одному вопросу, так что «отклонено» ничего
  не значит.

  Оставшиеся искажённые слова — два слова с латинской буквой внутри
  (`Видеокarta`, `брackete`); `rag_eval` считает только слова со смешанным
  алфавитом, а на этом нарочно плохом скане встречаются ещё несколько `Г6/c`
  вместо «Гб/с» и одно `Khonka` вместо «Кнопка».
- **Температура (правка 2).** RAGFlow шлёт вызовы зрения без параметров
  сэмплирования (`describe_with_prompt` в `rag/llm/cv_model.py`; `extra_body`
  у `OpenAI_APICV` всегда None), и vLLM подставляет чатовое умолчание LLM —
  температуру 0,7. Страница 10 скана, по пять прогонов собственным кодом
  RAGFlow:

  | Температура | Разных выводов | Таблица LAN расшифрована | Циклов | Время |
  |---|---|---|---|---|
  | 0,7 (как есть) | 5 из 5 | 5 из 5 | 0 | 21,5 с |
  | 0 | **1 из 5** | 5 из 5 | 0 | 22,0 с |
  | 0,2 | 4 из 5 | 5 из 5 | 0 | 22,1 с |

  На перерисованной копии той же страницы умолчание 0,7 в одной попытке из
  трёх заменило таблицы LAN и аудио заглушками картинок, и проиндексированный
  фрагмент потерял «Оранжевый — 1 Гбит/с»; при 0 вывод каждый раз совпадал
