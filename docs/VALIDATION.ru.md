# Журнал проверок

[English version](VALIDATION.md)

Разделы 1–5 — этап 3.1: доказательства для решений D8 и D14–D16 из
[DECISIONS.ru.md](DECISIONS.ru.md), собранные 2–7 октября 2026 года на одном
DGX Spark (GB10, DGX OS 7.5.0, драйвер 580.178.04, CUDA 13.0) с собственным
compose RAGFlow, образом RAGSpark `0.27.2-arm64-r1` и тремя контейнерами vLLM
в той же сети Docker. Раздел 6 — этап 3.2, собственный compose RAGSpark (D17).
Цифры можно воспроизвести скриптами из [tools/](../tools/).

## 1. Запуск LLM — Qwen 3.8 27B NVFP4

- Образ `vllm/vllm-openai:v0.27.1-aarch64`: vLLM 0.27.1, CUDA 13.0,
  вычислительная способность (12, 1). Чекпоинт NVFP4 распознаётся, выбирается
  `FlashInferCutlassNvFp4LinearKernel` — сборка сообщества не нужна.
- Веса загружаются из кеша примерно за 150 секунд; KV-кеш — около 814 тысяч
  токенов при `gpu_memory_utilization 0.50` (без MTP). Запуск с MTP и захватом
  CUDA-графов — около 7 минут.
- [model_probe.py](../tools/model_probe.py), 5 русских вопросов на режим:

  | Режим | Без MTP | MTP, 3 токена | Ответов с иероглифами |
  |---|---|---|---|
  | с рассуждениями | 10,3 ток/с | — | 0 из 5 |
  | без рассуждений | 10,2 ток/с | — | 0 из 5 |
  | без рассуждений, t=0,7 | 10,2 ток/с | — | 0 из 5 |
  | все режимы, MTP | — | **17,1 ток/с** (19–21 на ответах по контексту) | 0 из 15 |

- Рассуждения: тот же ответ занял 1116 токенов и 108 секунд с рассуждениями и
  101 токен и 10 секунд без них. Выключены на сервере флагом
  `--default-chat-template-kwargs '{"enable_thinking": false}'`; проверено, что
  запрос без параметров не возвращает поле `reasoning`.
- 8 параллельных запросов с MTP: все HTTP 200, по 25–27 секунд, суммарно около
  90 токенов/с; сервер не упал.
- Один из ранних пробных ответов содержал китайский фрагмент («相关信息»);
  приёмочная проверка должна продолжать искать иероглифы.

## 2. Регистрация моделей через API RAGFlow

Снято с веб-интерфейса RAGFlow 0.27.2 и автоматизировано в
[ragflow_models.py](../tools/ragflow_models.py):

| Шаг | Запрос | Тело / примечания |
|---|---|---|
| вход | `POST /api/v1/auth/login` | `{email, password}`; пароль шифруется RSA ключом `conf/public.pem` (`api.utils.crypt.crypt`). Токен приходит в **заголовке ответа** `Authorization`, без `Bearer` |
| подключить провайдера | `PUT /api/v1/providers` | `{"provider_name": "VLLM"}` |
| проверить адрес | `POST /api/v1/providers/VLLM/connection` | `{provider_name, api_key: "", base_url}` |
| модели на сервере | `GET /api/v1/providers/VLLM/models?api_key=x&base_url=…` | возвращает `name`, `model_types` (определяется верно: chat / embedding / rerank), `max_tokens` из vLLM |
| создать экземпляр | `POST /api/v1/providers/VLLM/instances` | `{instance_name, api_key: "", base_url, model_info: [{model_name, model_type: [тип], max_tokens, extra: {is_tools}}]}`; пустой ключ сохраняется как `"x"` |
| список экземпляров | `GET /api/v1/providers/VLLM/instances` | в списке **нет `base_url`**; его даёт `GET …/instances/<id>` |
| изменить экземпляр | `PUT /api/v1/providers/VLLM/instances/<id>` | полная запись |
| идентификаторы моделей | `GET /api/v1/models` | `model_id`, `name`, `instance_name`, `model_type` для каждой модели; идентификатор модели отличается от идентификатора экземпляра |
| назначить по умолчанию | `PATCH /api/v1/models/default` | `{model_id, model_type}`; интерфейс сохраняет каждое поле сразу |
| прочитать умолчания | `GET /api/v1/models/default` | хранится по `model_id`; имена подбираются заново, поэтому устаревший идентификатор может показывать совпадающие имена |
| поиск | `POST /api/v1/retrieval` | `{dataset_ids, question, similarity_threshold, vector_similarity_weight, rerank_id: "BAAI/bge-reranker-v2-m3@ragspark-rerank@VLLM", page_size, rerank_candidates_count}` |

Успешный ответ всегда содержит `{"code": 0}`. Модели живут в учётке
администратора (`tenant_name: "admin’s Kingdom"`).

## 3. Загрузка документов

- **DOCX** (18 KB, русский текст с командами): 3 фрагмента, около 1,5 секунды
  от старта до индекса; три запроса `POST /v1/embeddings` дошли до vLLM.
  Обработчик задач работает без NATS — очереди в Valkey. Строки склеиваются без
  разделителя (`GPUКритерий`): 11 таких мест.
- **PDF** (русская инструкция к материнской плате на 39 страниц, текстовый слой
  есть):

  | Парсер | Время | Фрагментов | Доля кириллицы | Искажённых слов |
  |---|---|---|---|---|
  | DeepDOC | ~2 мин (распознавание 7–9 с, макет ~8 с, таблицы 4–39 с на 12 страниц) | 100 | 0,665 | 194 |
  | Naive | секунды | 41 | **0,835** | **0** |

  Эталон 0,835 — собственный текстовый слой PDF (`pdftotext`).
- Причины в DeepDOC, по исходникам 0.27.2:
  - `deepdoc/parser/pdf_parser.py`, проверка «искажённой кодировки шрифта» на
    уровне страницы: если ≥30% символов страницы из подмножеств шрифтов, <5% —
    иероглифы и >40% — знаки препинания ASCII, текст страницы выбрасывается и
    она распознаётся как картинка. Срабатывает на точках-заполнителях оглавления.
  - Модель распознавания — иероглифы и латиница. Защита от повторного
    распознавания кириллицы есть на уровне отдельных блоков
    (`_ocr_can_represent`), но не в проверке страницы.

## 4. Поиск

Итоговая оценка с реранкером (`rag/nlp/search.py`, `rerank_by_model`):
`(1 − w) × совпадение слов + w × оценка реранкера`, сравнивается с порогом
сходства; `w` — вес векторного сходства.

- С настройками RAGFlow по умолчанию (`w` = 0,3, порог 0,2) нужный фрагмент
  DOCX набрал 0,7 × 0,154 + 0,3 × 0,293 = **0,196** и был отброшен.
- [rag_eval.py](../tools/rag_eval.py) на PDF (Naive), 8 вопросов с ответом и 2
  без ответа:

  | Настройка | До правки: найдено / отсеяно | После правки: найдено / отсеяно |
  |---|---|---|
  | реранкер, 0,3 / 0,2 | 5/8 · 1/2 | 6/8 · 1/2 |
  | реранкер, 0,7 / 0,2 | 5/8 · 2/2 | 7/8 · 2/2 |
  | реранкер, 0,7 / 0,1 | 6/8 · 2/2 | **8/8 · 2/2** |
  | без реранкера, 0,7 / 0,2 | 8/8 · 0/2 | 8/8 · 0/2 |
  | без реранкера, 0,7 / 0,5 | 8/8 · 0/2 | 8/8 · 0/2 |

  Без реранкера вопросы без ответа получили 0,58 — столько же, сколько
  настоящие ответы (0,56–0,62).
- Причина низких оценок реранкера: RAGFlow отправляет ему
  `remove_redundant_spaces(" ".join(tokens))`. Первое регулярное выражение
  функции, `([^a-z0-9.,\)>]) +([^ ])` → `\1\2`, удаляет все пробелы после
  нелатинских символов:

  ```
  "оранжевый 1 гбит с подключение таблица состояний индикатора порта lan"
  → "оранжевый1гбитсподключениетаблицасостоянийиндикаторапортаlan"
  ```

  Английский текст не страдает. Тот же фрагмент, оценённый напрямую
  (`--probe`):

  | Вопрос | Склеенные токены (RAGFlow) | Исходный текст | Только строки с ответом |
  |---|---|---|---|
  | объём памяти | 0,152 | 0,116 | 0,047 |
  | оранжевый индикатор LAN | 0,373 | 0,457 | 0,285 |
  | размеры для M2_2 | 0,320 | 0,640 | 0,960 |

  Токены имени файла, которые RAGFlow дописывает к фрагменту, меняли оценку
  меньше чем на 0,05. LLM не затронута: она получает исходный текст фрагмента.
- Исправление: [patch_search.py](../build/ragflow/patch_search.py) (образ `r2`)
  — реранкер получает исходный текст фрагмента вместе с его ключевыми словами и
  сгенерированными вопросами. Проверено правкой прямо в работающем контейнере,
  а 8 октября 2026 года — на образе `r2`: таблица та же.

## 5. Полный путь

- Чат с Qwen 3.8, база знаний с DOCX, реранкер, `w` = 0,7, порог 0,2:
  «Какая максимальная температура GPU допустима при стресс-тесте?» →
  «≤80 °C, пик ≤90 °C» со ссылкой на источник, на русском.
- Вопрос, ответа на который в документах нет, вернул заданный текст «Empty
  response». RAGFlow отдаёт его, не вызывая LLM, когда ничего не прошло порог,
  поэтому модели нечего выдумывать.
- Новые базы знаний и чаты получили LLM и модель эмбеддингов по умолчанию;
  реранкер пришлось выбирать вручную (D8).

## 6. Compose RAGSpark (этап 3.2)

Доказательства для D17, собранные 8 октября 2026 года на том же DGX Spark с
Docker 29.6.2 и Compose v5.2.0: [compose/](../compose/) запущен с пустыми
томами, веса уже лежали в `/srv/ragspark/hf-cache`.

- **Порядок и время запуска** (`docker compose up -d --wait`, моменты старта
  из `docker inspect`):

  | Шаг | Время |
  |---|---|
  | `vllm-embed` до готовности | 36 с |
  | `vllm-rerank` до готовности | 36 с |
  | `vllm-llm` (Qwen 3.8, MTP) до готовности | 7 мин 11 с |
  | `ragflow` до готовности | ~46 с |
  | **весь стек** | **9 мин 10 с** |

  Базы данных стали готовы параллельно с моделями. Проверка готовности идёт раз
  в 20 секунд, поэтому точность каждого шага — около 20 секунд.
- **Перезапуск LLM** (`docker compose restart vllm-llm`): 332 секунды вместо
  431. Кеш компиляции в томе `vllm-compile-cache` экономит около четверти
  времени; загрузка весов и захват CUDA-графов повторяются.
- **Доступ снаружи:** единственный слушающий `docker-proxy` — `0.0.0.0:80`.
- **Часовой пояс:** контейнер RAGFlow показывает время хоста (MSK).
- **Состояние:** `/api/v1/system/healthz` вернул `ok` для MySQL,
  Elasticsearch, Valkey и хранилища.
- **Память при простое стека:** занято 86 GiB, файловый кеш 35 GiB, доступно
  34 GiB. Модели запустились без предварительного освобождения кеша.
- **Суперпользователь:** RAGFlow создал `admin@ragspark.local` из
  `DEFAULT_SUPERUSER_EMAIL`; адрес принимают и API, и веб-интерфейс.
- **Модели:** на пустой базе [ragflow_models.py](../tools/ragflow_models.py)
  подключил провайдера VLLM, создал три экземпляра и назначил модели по
  умолчанию; повторный запуск показал везде `[OK]`. Новая база знаний сама
  получила модели эмбеддингов и индексации по умолчанию.
- **Поиск:** те же два документа, загруженные заново (PDF с разборщиком Plain
  Text), дали ровно результаты этапа 3.1 — у PDF 41 фрагмент, доля кириллицы
  0,835, искажённых слов нет; таблица [rag_eval.py](../tools/rag_eval.py)
  совпала до ячейки, **8/8 найдено · 2/2 отсеяно** с настройками RAGSpark
  (реранкер, 0,7 / 0,1).
- **LLM изнутри стека** ([model_probe.py](../tools/model_probe.py) в
  контейнере RAGFlow): 16,5–17,0 токена/с, иероглифов нет ни в одном из 15
  ответов. Режим «с рассуждениями» так же быстр, как остальные: сервер
  выключает рассуждения, если запрос не просит их явно.
